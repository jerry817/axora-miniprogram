# AI 白名单部署与维护

## 1. 首次部署

1. 使用微信开发者工具打开项目，并确认 `app.js` 中的云开发环境 ID 指向要使用的环境。
2. 在云函数目录中，分别右键 `authUser` 和 `chatAI`，选择「上传并部署：云端安装依赖」。`chatAI` 仍需保留现有的 `DEEPSEEK_KEY` 云函数环境变量。
3. 打开「云开发控制台 → 数据库」，创建集合：`ai_whitelist`。
4. 集合权限保持为仅云函数可读写（客户端不应能直接修改白名单）。

## 2. 添加一个用户

每个用户的 OpenID 都是这个小程序和云环境内的稳定 ID；不要使用昵称或头像作为权限依据。

1. 请用户在「我的」页完成一次登录。若用户不在白名单，会显示「抱歉，您未在白名单内，请联系开发者」。
2. 在「云开发控制台 → 云函数 → authUser → 日志」中查找 `AI whitelist check`，复制该条日志中的 `openid`。
3. 在 `ai_whitelist` 集合新增一条记录：

```json
{
  "_id": "替换为日志中的 openid",
  "enabled": true,
  "note": "姓名或用途（可选）"
}
```

4. 让用户再次点「微信登录」。登录成功后，「我的 → 用户 ID」可复制其当前 OpenID 以便复核。

`_id` 必须就是 OpenID，且 `enabled` 必须为布尔值 `true`。同一个 ID 只能有一条记录。

## 3. 停用或移除用户

- 临时停用：把该记录的 `enabled` 改为 `false`。
- 永久移除：删除该记录。

下一次 AI 请求会立即由 `chatAI` 云函数重新检查白名单，因此即使用户设备仍保留旧登录信息，也不能继续调用 AI。

## 4. 验证清单

1. 用未添加的测试账号登录：应出现指定的白名单弹窗，且调用 AI 失败。
2. 将该账号的 OpenID 加入集合后重新登录：应出现登录成功，并能在「我的 → 用户 ID」复制 ID。
3. 发送一条 AI 消息：应正常得到回复。
4. 将 `enabled` 改为 `false` 后再次发送：应再次出现白名单弹窗。

## 隐私说明

当前微信小程序规则下，不能再用 `wx.getUserProfile` 直接读出微信账户原始头像和昵称。项目已改为让用户通过 `chooseAvatar` 和 `type="nickname"` 控件主动选择/填写展示信息；OpenID 则由云函数从调用上下文中可信地取得，前端无法伪造。
